# 五分钟演示脚本

给第一次看这个平台的人演示时，按这个顺序走。每一步都有「点什么」和「应该看到什么」，
看到的和写的不一样，就是有问题。

## 0. 开场（30 秒）

一句话说明这是什么：

> 业务对象、属性、关系、动作用一份声明式本体描述，Agent 能直接读写这份本体；
> 改模型、跑规则、执行业务动作，都在同一个地方，而且每一次改动都能回查。

## 1. 平台总览（40 秒）

点左侧 **平台总览**。

**应该看到**：本体对象数、业务规则数、业务动作数、对象关系数四个数字；
下面「能力闭环」四段（业务知识建模 → 语义建模 → Harness 执行 → 业务应用自动化）。

**说**：数字都来自磁盘上那份本体文件，不是写死的。

## 2. 本体模型：看清楚一个对象（60 秒）

点 **本体模型** → 左侧点 **库存**。

**应该看到**：
- 右侧详情：8 个属性，类型和必填标记
- 「关系」：`belongsTo → Store`、`references → Product`
- 「动作」：三个动作，标了需审批/免审批
- 「模型影响分析」：改这个对象会波及什么

**说**：这是给人和 Agent 看同一份定义——不是文档，是能校验的数据。

## 3. 改模型：建一个对象（60 秒）

点对象清单右上角 **+ 新建**，填：

| 字段 | 值 |
| --- | --- |
| 对象 ID | `Depot` |
| 中文名 | `转运仓` |

保存。

**应该看到**：
- 清单从 6 个变成 7 个，新对象立刻出现
- 不用手动刷新

**说**：保存前会按整包校验，写错了贴在你眼前，磁盘不会被动。

## 4. 图谱：拖一下（30 秒）

点 **图谱**。

拖动任意一个节点。

**应该看到**：节点跟着走，松手后位置保留（刷新还在）。

**说**：这只是布局，不动本体。从节点右侧圆点拖到另一个节点才是真的建关系。

## 5. 跑规则（40 秒）

点 **逻辑与动作** → **在示例数据上跑一次**。

**应该看到**：违规条数、涉及哪几条规则、具体哪些行。

**说**：规则不是文字说明，是在示例数据上真求值的。

## 6. 业务动作 + 审批（60 秒）★ 重点

这一步要 Agent 配合。在对话里说：

```
跑调拨：S-0213 的 SKU-1001 转 30 件到 S-0188
```

**应该看到**：
1. 弹出审批卡片，显示「发起调拨」和四个入参
2. 点**同意**
3. 数据变化：S-0213 `80 → 50`，S-0188 `95 → 125`
4. 变更历史多一条 `execute_action`

**说**：这是整个平台最关键的一条——**Agent 想改业务数据，必须过人这一关**。
点拒绝就什么都不写。

> 如果没弹卡片，先查权限预设：`danger-full-access` 的审批策略是 `never`，
> 要换成 `workspace-write` 或 `read-only`，且必须**新开会话**才生效。

## 7. 收尾（20 秒）

点 **治理中心** → 「本体体检」卡。

**应该看到**：六个方面几项就绪、缺什么、怎么补。

**说**：这份本体作为 Agent 的底座还缺什么，它自己会说。

## 演示时容易被问到的三个问题

**Q：数据从哪来？**
A：现在跑的是 `assets/*.records.json` 里的示例数据，真实数据源要接连接器（还没做）。

**Q：Agent 能直接改吗？**
A：写操作要走审批；还有只读门禁，开了之后写工具根本不注册，Agent 看不到。

**Q：和普通建模工具的区别？**
A：这里的本体是给机器消费的——有校验、有影响分析、有规则求值、有动作执行、有变更历史。
不是画给人看的图。

## 别演砸的四个坑

1. **面板显示「演示数据」** → 宿主没连上，或客户端是旧版本，按 Ctrl+Shift+R
2. **审批卡片不弹** → 权限预设是 `danger-full-access`（`approval: never`）
3. **改动没生效** → 先看自检「版本一致」那行，可能是宿主半没重载
4. **图谱节点拖不动** → 窗口太窄，先最大化
